# ナビ 実装計画

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 町の中の曲がる案内と車線の案内、高速の出口の車線案内、道を外れたときの探し直し、どの視点でも見える小さな案内の札、止まって見る全体地図を作る。

**Architecture:** 道探しと案内は DOM なしのファイル `src/02e-nav.js`（つながり表・道探し・位置合わせ・案内・探し直し）にまとめ、Node のテストで確かめる。ゲームの中の区間の判定と `navState()` は `13-game.js`、運転席の画面は `08-dash.js`、小さな札と全体地図は新しい `08b-navmap.js` と `page.html`。

**Tech Stack:** Three.js r128、素の JavaScript（グローバルスコープ、`build.mjs` が名前順につなぐ）、`node --test`、Playwright（headless Chromium + swiftshader）。

**Spec:** `docs/superpowers/specs/2026-11-12-nav-design.md`

## Global Constraints

- ゲームは 1 つの HTML にまとまる。絵はコードで描く。外部の画像・フォントを足さない。実在の会社名・店名は入れない。
- 物理・町の形・町の車・仕事の決まりは変えない。変えるのは案内と表示、地図を開いている間の止め方だけ。
- 町の座標は C1 と同じ（`u`、`v`）。町の中の向きは角度 `θ = atan2(dv, du)`、世界の向きは `site.hu + θ`。道の向き `'u+' = 0`、`'v+' = π/2`、`'u-' = π`、`'v-' = −π/2`。`θ` が +90° 回ると左（左側通行で左折は曲がりやすい方）。
- 道探しの点数：距離 ×（大通り 1.0、脇道 `NAV_SIDE = 1.4`）、左折 +15、右折 +60（`NAV_TURN = { left: 15, right: 60 }`）、門に入る・門から出るも同じ。U ターンは計画しない。町の端の閉鎖された道の先は表に入れない。
- 探し直し：ルートにない道に 5 m 以上入った、ルートの道を逆向きに 15 m 以上走った、ルートの道から 20 m 以上離れて 2 秒。続けて探すときは 3 秒あける。知らせ「ルートを探し直しました」は 2 秒。構内と広場では探し直さない。
- 案内の文（`navText(kind, name)`、そのまま使う）：`left` 左折、`right` 右折、`straight` 直進、`gateLeft` 門は左、`gateRight` 門は右、`outLeft` 門を出て左、`outRight` 門を出て右、`plaza` 広場へ、`arrive` 到着、`etcIn` ETC 入口 20km/h 以下、`etcOut` ETC 出口 20km/h 以下、`ramp` 料金所 ETC は 20km/h 以下、`merge` 本線へ合流　右、`exitLane` `${name}IC 出口　左車線へ`、`exit` 出口　左、`dock` 荷台口にバックで（+20%）、`bay` 納品の枠へ。連結前は「トレーラーを連結してください」、知らせは「ルートを探し直しました」（どちらも今のまま `navState` が出す）。
- 町の距離は実寸（m、10 m 単位で表示）。高速の表示の距離は今のまま（ゲームの m × `SCALE`）。仕様の「出口の 2 km 手前」は 2km の出口予告の標識の位置（`r.sDiv − 700`）から、「300 m 手前」は 500m の標識の位置（`r.sDiv − 160`）から。標識と案内がそろう。
- 小さな札を出すとき：町で次の曲がり（`left`・`right`・門・`plaza`）が 300 m 以内、広場、構内、入口の帯、高速で `s ≥ r.sDiv − 700`（目的の出口）。そのほかは隠す。
- 上限：道探し 1 回 1 ms 未満（Node、13 町 × 全倉庫の平均）、`drawNav` 1 回 3 ms 以内（ブラウザ）、全体地図を開いたときの 1 回の描画 30 ms 以内。
- ソースはグローバルスコープ。新しい名前（`NAV`、`NAV_TURN`、`NAV_SIDE`、`navGraph`、`navRoute`、`navMatch`、`navGuide`、`navFollow`、`navText`、`navCardUpdate`、`mapOpen`、`mapClose`、`drawMap`）がほかのファイルとぶつからない（`test/math.test.mjs` が見張っている）。`02e-nav.js` は `test/helpers/sim.mjs` の `PURE` と `NAMES` に足す。
- 今あるテスト（`npm test` 95 件、`npm run e2e` 80 件）が通り続ける。ナビの文が変わるテスト（`dash.e2e.mjs` の C1 の町の案内）は新しい文に書き直す。e2e は 1 ファイル 10 分まで。
- コミットのたびに `node build.mjs` で `index.html` を作り直して一緒にコミットし、`git push -u origin claude/nippon-long-haul-game`。プルリクエストは作らない。コミットメッセージの最後に、セッションの指示にある帰属の 2 行を付ける。

## Review Focus

1. 交差点の中で曲がっている途中（どの道の上か決まらない間）に、間違って探し直さない。→ Task 2 のテスト「交差点を曲がるあいだは探し直さない」。
2. 出発の構内から、案内と逆の向き（右）へ出ても、U ターンではなく街区を回る道で探し直す。→ Task 2 のテスト「門を出る向きを間違えても、U ターンなしで探し直す」。
3. 目的地が途中で変わる（出口を過ぎた、目的の町から入口で高速に戻った）と、ルートの終わりも変わる。→ Task 3 のテスト「目的地が変わるとルートの終わりも変わる」。
4. 町の中で保存して開き直した直後から、案内が出る。→ Task 3 のテスト「町の中で再開した直後から案内が出る」。
5. ルートが作れない町（簡単な構内に切り替わった町）では、C1 の仮の案内に戻り、例外を出さない。→ Task 1 のテスト「簡単な構内の町では道探しが null」と Task 3 のテスト「ルートがない町では仮の案内」。

**Interfaces:**
- Consumes: `layout.streets`（`id, kind, axis, c, a0, a1, lanes, laneW, walkW`）、`layout.nodes`（`id, u, v, streets: [V.id, U.id], arms`）、`layout.warehouses[k].gate`（`u, v, nu, nv`）と `.street`。
- Produces:
  - `navGraph(L)` → `{ nodes: [{ id, u, v }], edges: [{ id, from, to, street, dir, len, main, a: [u, v], b: [u, v] }], out: Map<nodeId, edgeId[]>, plaza: nodeId }`。`layout` ごとに `WeakMap` で覚える。`plaza` は大通り A の `v = a0`（45）の点で、大通り A の最初の交差点と行き・帰りの 2 本でつなぐ。
  - `navRoute(L, from, to)`：`from` は `{ edge, d }`（向きのある道の上、始まりから `d` m）、`{ gate: wh }`、または `{ plaza: true, start: true }`（広場から大通り A を `v+` へ）。`to` は `{ gate: wh }` または `{ plaza: true }`。→ `{ edges: [edgeId], cost, steps: [{ kind, at: [u, v], edge, dist }] }` または `null`。`steps` は曲がる所と終わりだけ（直進で通る交差点は入れない）。`dist` は始まりからその所までの道のりの m。最後の `step` は `gateLeft | gateRight | plaza`。門から始まるときは最初の `step` が `outLeft | outRight`。
  - `navText(kind)` → グローバル制約の文。
  - 道の向きと曲がりの判定：向きの角度の差が +90° なら `left`、−90° なら `right`、0 なら直進、180° は使わない。門は、進む向きの左にあれば `gateLeft`。
